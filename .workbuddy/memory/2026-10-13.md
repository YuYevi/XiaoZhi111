# 2026-10-13

## 小智固件串口日志分析（用户板：AI-dual-eyed-doll，固件基于 xiaozhi-esp32 v2.4.0）

- 问题1（配网成功后 ~48s 才弹激活码）：耗时主要在配网结束后的 WiFi 重连——softAP 拆除、APSTA→STA 切换后约 10ms 即发起全信道扫描，前两次（79.4s、91.8s）均返回空（目标 AP 信号 -28dBm，排除射频因素），叠加 esp-wifi-connect 默认 10s→20s 指数退避，合计 ~37.2s（占 77%）。激活逻辑本身仅 ~1s（激活码就在 OTA 检查的同一 HTTP 响应里返回）。官方当前 main 已升级 esp-wifi-connect 3.3.x，用「已保存信道优先扫描 + WIFI_FAST_SCAN」把重连压到 1-3s。
- 问题2（激活后唤醒无效）：根因是唤醒词模型完全没加载，与麦克风基本无关。证据：MODEL_LOADER: Can not find model in partition table（esp-sr src/model_path.c）→ AFE_CONFIG: wakenet model not found → AFE pipeline 无 WakeNet 级 → detector: none。板子两条官方模型加载路都断：①assets 分区被禁用（Assets partition is disabled，官方 v2 主路：assets→index.json→srmodels.bin→srmodel_load→SetModelsList）；②分区表无 model 分区（v1 备路：esp-sr CMake 自动打包烧录 srmodels.bin，但分区表缺 model 时构建静默跳过、不报错）。
- 修复方向：A) 分区表加 assets 分区走官方主路；B) 分区表加 model 分区（如 partitions/v1/16m_custom_wakeword.csv 样式）+ menuconfig 选唤醒词（你好小智 wn9s_nihaoxiaozhi）+ idf.py flash 自动烧 srmodels.bin。修好标志：日志出现 Model 0: ...、pipeline 含 |WakeNet|、detector: WakeNet。
- 顺带：设备从 factory 分区运行 → OTA 升级被跳过（Running from factory partition, skipping），升级需 USB 重刷或改 ota_0/ota_1 分区表；assets 禁用同时导致无主题/字体/表情；60s 连接超时差一点回退配网模式。
- 参考源码已浅克隆至 /tmp：xiaozhi-esp32（v2.4.0 与 main）、78/esp-wifi-connect（3.3.1）、espressif/esp-sr。

## 两个问题的修复实施（工作区 XiaoZhi111 = xiaozhi-esp32 fork，板子 AI-dual-eyed-doll）

- 问题2 修复（唤醒词）：新增 `partitions/v2/4m_model.csv`（model 384KB@0x10000 / factory 2.5MB@0x70000 / assets 1MB@0x300000 不变），`main/boards/AI-dual-eyed-doll/config.json` 指向新表；唤醒词选择本就在 `sdkconfig.defaults.esp32s3`（wn9_nihaoxiaozhi_tts「你好小智」）。esp-sr CMake 检测到 model 分区后自动打包烧录 srmodels.bin。构建验证通过：srmodels.bin 291KB（esp-sr 建议 ≥286K）、xiaozhi.bin 2,435,520B < factory 2,624KB（9% 余量）、merged-binary.bin 3.57MB、flash_args 确认 srmodels@0x10000。分区布局变更必须整包 USB 重刷（本板 factory 运行，OTA 本就跳过）。

- 文档：板子 README 增加「唤醒词与分区表」小节；`scripts/dual_eye_anim/verify_partition_image.py` 注释中的分区表名同步更新。
